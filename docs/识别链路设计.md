# 识别链路设计（内部技术文档）

> 业务侧只调用**一个**视觉多模态大模型（VL）接口完成「识别 + 抽取 + 整理」，
> 检索链路只依赖 Embedding / Reranker 两个标准接口。三者均为外部独立部署的推理服务，
> 通过 OpenAI 兼容协议（HTTP + Key）调用，与本系统完全解耦。

## 1. 版式自适应分流

**问题**：刻本正文/多栏/表格是规则单一结构，世系表是不规则复杂结构，一刀切识别效果差
——规则版式整页喂模型会跨栏横拼，世系表切列则直接崩坏。

**方案：先判页型，再分流识别**

```
整页识别成功 → 判型（按模型输出的版面类别）
  ├─ 规则版式（刻本正文 / 多栏 / 表格）→ 「列边界对齐竖切」重跑
  │        沿列间空白竖切、绝不切穿列；竖排从右到左逐组读
  └─ 世系表（不规则版式）→ 保持整页精读
```

判型以模型输出的版面类别为主，类别缺失时用列几何质量兜底。

**回退**：`.env` 设 `OCR_LAYOUT_MODE=whole` 即可关闭分流、回到纯整页识别，无需回滚代码。

## 2. 稳定性设计

古籍扫描件的典型故障是**模型死循环**与**大图超时**，针对性处理：

1. **图像预处理**：页面长边统一压到 `MAX_IMAGE_LONG_EDGE`（默认 1600px），可选去噪/纠偏/增强。
   大图会让视觉 token 暴涨，压缩后既避免超时又保留字迹；空白页预检直接跳过，减少无效调用。
2. **输出熔断**：重复块检测 + 输出字符上限 + 单页硬超时（`VLM_PAGE_TIMEOUT`），
   异常页判失败跳过，不拖垮整卷。
3. **两段式处理**：拆为「识别 + 初步整理」与「最终整理」两段——识别阶段关思考保速度，
   整理阶段开思考保准确，兼顾效率与跨页关系连续性。
4. **兜底链路**：整页失败自动分块重试（横向/纵向），块级失败可逐块容错。

## 3. 业务流程

```
扫描件上传 → 转图预处理 → AI 识别 + AI 初步整理 → 人工审核 → AI 最终整理 → 写入图谱
```

- **上传转图**：批量上传、单文件最大 1G、SHA-256 内容级查重、同名预检；转图多线程并行。
- **任务调度**：滑动窗口 + 任务排队，支持断点续跑、失败页重试、任务暂停/继续。
- **AI 识别**：逐页调用 VL 服务，返回结构化 JSON（人物 + 关系 + 正文 + 置信度）。
- **人工审核**：整卷/逐页双模式、放大浮窗对照、繁简切换、增删改；机制为「见错即删，剩余全入」。
- **整理入库**：审核通过后 AI 整卷最终整理（开启思考），写入 Neo4j 图谱。

> 系统价值 = 把"纯手工录入"变成"校对修正"。
